# Standard workflow

1. Identify purpose, audience, confidentiality, organizational or academic context, and requested formats.
2. Retrieve durable user preferences when available. Apply only preferences whose scope matches the current context; never transfer a work brand into academic or unrelated material. If context is ambiguous and identity would materially change, ask instead of guessing.
3. Select the closest existing template, form pattern and brand tokens. Treat preferences as a starting hypothesis, not permission to bypass source assets or explicit brand guidance.
4. Build a conclusion-led storyline and `DocumentSpec`.
5. Validate sources, assets and schema.
6. Generate chart/diagram assets.
7. Render with local Typst, PptxGenJS and/or docx.js.
8. Run structural checks and generate previews.
9. Inspect every page/slide using `visual-qa`; compare requested formats for hierarchy, density and semantic parity rather than pixel identity.
10. Apply layout/content-structure fixes without changing facts.
11. Repeat at most three times and report any remaining issue.
12. Publish under `artifact-studio/artifacts/output/`.
